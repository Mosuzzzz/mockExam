# MockTest

MockTest turns practice questions generated by an external LLM into a validated, timed multiple-choice exam. Question generation stays in the tool the student already uses.

## Run locally

1. Install Bun, then run `bun install` from the project root.
2. Copy `.env.example` to `.env` and add your Clerk development keys.
3. In the Clerk Dashboard, enable Google and GitHub as the only sign-in methods, then allow `http://localhost:5173` as a redirect/origin.
4. Run `bun run dev` and open `http://localhost:5173`.

The first development database is created under `data/`. Do not commit `.env` or database files.

## Clerk setup

The app uses Clerk's React components and verifies bearer session tokens on the API. Set `VITE_CLERK_PUBLISHABLE_KEY`, `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, and `CLERK_AUTHORIZED_PARTIES` in the root `.env`. The two publishable-key variables contain the same public key; the secret stays server-side. Configure Google and GitHub in Clerk's social connections and disable other sign-in methods to match the MVP requirements.

In production, set `CLERK_AUTHORIZED_PARTIES` to the exact HTTPS origin of the deployed app, build the frontend, and run the Bun API on a host with persistent writable storage. The API serves `apps/web/dist` when that folder exists, keeping the browser and API on one origin.

## Useful commands

- `bun run dev` — web and API development servers.
- `bun run build` — production web bundle.
- `bun run typecheck` — type-check the shared package, API, and web app.
- `bun run test` — shared validation and server scoring unit tests.
- `bun run db:generate` — create a Drizzle migration from the schema.
- `bun run db:migrate` — apply pending SQLite migrations.
- `bun run start` — apply migrations and start the production API.

## JSON format

The single source of truth is `packages/shared/src/schema.ts`. A copyable prompt for compatible JSON is in `docs/MockTest JSON Prompt.md`; a sample import is in `docs/sample-mocktest.json`.
