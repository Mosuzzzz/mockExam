# MockTest — Project Overview

## Summary
MockTest is a lightweight web application that converts mock-exam JSON generated by **any LLM** (ChatGPT, Gemini, Claude, local models, etc.) into a proper timed exam experience.

The application does **not** call an AI API. The student generates questions externally, then pastes or uploads the resulting JSON into MockTest.

**Core flow:**

`Any LLM → MockTest JSON → Validate → Timed Exam → Score & Review → Saved History`

## Problem
Students often use LLMs to create practice questions before midterm and final exams, but the chat experience is not a real exam environment. Answers may be visible too early, there is no consistent timer/navigation, and previous attempts are difficult to track.

## Solution
MockTest provides:
- Sign in with **Google or GitHub only**, managed by **Clerk**
- No username/password authentication
- Paste or upload `.json` mock tests
- Strict JSON validation
- Timed multiple-choice exams
- Previous/Next and direct question navigation
- Manual or automatic submission
- Score, percentage, correct/incorrect review, and explanations
- Saved tests and persistent attempt history
- Retake support
- A copyable prompt for generating compatible JSON in any LLM

## MVP Stack
- **Runtime / package manager:** Bun
- **Frontend:** React + Vite + TypeScript
- **Backend:** ElysiaJS
- **Authentication:** Clerk
- **OAuth providers:** Google + GitHub only
- **Validation:** Zod
- **ORM:** Drizzle ORM
- **Database:** SQLite
- **Styling:** Tailwind CSS + selective shadcn/ui
- **Testing:** Playwright + focused unit tests
- **AI integration:** None; users generate JSON with their preferred LLM

## Lightweight Design Decisions
The MVP intentionally avoids:
- Built-in LLM APIs
- Next.js server framework features
- Prisma
- PostgreSQL
- Redis
- Microservices
- Username/password authentication
- Local authentication/session tables
- Separate `questions` and `attempt_answers` database tables

Instead, Clerk owns identity/session management, while the application stores only the **Clerk user ID** as the owner reference for tests and attempts. Each imported test and submitted answer set can be stored primarily as JSON, keeping the database and backend small.

## Architecture

```text
                 │
                 ▼

```

## Core Data Model
### `mock_tests`
Stores `id`, `clerk_user_id`, metadata, question count, the complete `test_json`, and timestamps.

### `attempts`
Stores `id`, `clerk_user_id`, `mock_test_id`, `answers_json`, score, total questions, percentage, and timestamps.

Clerk manages user identity and sessions externally, so the MVP does not need local password, account, or session tables.

## MockTest JSON v1
```json
{
  "version": "1.0",
  "title": "Database Midterm",
  "description": "Practice for Chapters 1-5",
  "duration_minutes": 60,
  "questions": [
    {
      "id": "q1",
      "type": "multiple_choice",
      "question": "What is a primary key?",
      "options": [
        "A unique identifier for a row",
        "A table name",
        "A database server",
        "A SQL keyword"
      ],
      "answer": 0,
      "explanation": "A primary key uniquely identifies each row."
    }
  ]
}
```

## MVP Pages
- `/` — Landing page and Clerk sign-in controls
- `/dashboard` — Saved tests and latest attempts
- `/create` — Paste/upload JSON and validate it
- `/exam/:testId` — Timed mock exam
- `/result/:attemptId` — Score and answer review
- `/history` — Completed attempt history

## Version 1 Goal
A production-ready V1 is complete when this flow works reliably:

**Clerk Login → Import JSON → Validate → Save Test → Take Timed Exam → Submit → Review Result → Persist History → Retake**
