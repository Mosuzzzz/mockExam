# MockTest Software Requirements

## 1. Purpose

MockTest converts multiple-choice JSON generated by an external study tool into a validated, timed exam. It stores tests and attempt history in a local PostgreSQL database and provides answer review after submission.

Question generation stays outside the application. MockTest does not call an AI API.

## 2. Operating scope

MockTest is a local-only application for one workspace. It does not have accounts, identity management, or user separation. The web app, API, and PostgreSQL service are run locally with Bun and Docker Compose.

### Stack

| Area | Technology |
| --- | --- |
| Runtime and package manager | Bun |
| Frontend | React, Vite, TypeScript |
| API | ElysiaJS |
| Validation | Zod |
| ORM and migrations | Drizzle ORM |
| Database | PostgreSQL 17 in Docker Compose |
| Styling | Tailwind CSS |

## 3. Users and external systems

The local user imports a test, completes an exam, reviews results, and may retake the test. An external LLM or study tool may generate compatible JSON, but has no direct connection to MockTest.

## 4. Functional requirements

| ID | Requirement |
| --- | --- |
| FR-01 | Show the local workspace and saved tests at `/` and `/dashboard`. |
| FR-02 | Accept MockTest JSON by paste or `.json` file upload. |
| FR-03 | Validate imports in the browser and again in the API before saving. |
| FR-04 | Limit imports to 1 MiB, tests to 1–100 questions, and duration to 1–180 minutes. |
| FR-05 | Require unique question IDs, four options per question, and an answer index from 0 to 3. |
| FR-06 | List saved tests with attempt counts and latest completed results. |
| FR-07 | Delete a test and all its attempts. |
| FR-08 | Start a timed attempt or resume an existing active attempt for that test. |
| FR-09 | Save answer changes with revision checks so stale requests cannot overwrite newer answers. |
| FR-10 | Keep the test's answer keys and explanations out of active exam responses. |
| FR-11 | Grade using the saved test and validated answers on the API. |
| FR-12 | Finalize expired attempts from their latest saved answers on the next relevant request. |
| FR-13 | Show score, percentage, answer outcomes, correct answers, and explanations after completion. |
| FR-14 | List completed attempts newest first and allow a fresh retake. |
| FR-15 | Copy or download incorrect and unanswered questions as `mocktest.missed-questions.v1` JSON. |

## 5. MockTest JSON v1

```json
{
  "version": "1.0",
  "title": "Database Midterm",
  "description": "Practice for Chapters 1-5",
  "duration_minutes": 60,
  "questions": [
    {
      "id": "q1",
      "type": "multiple_choice",
      "question": "What is a primary key?",
      "options": [
        "A unique identifier for a row",
        "A table name",
        "A database server",
        "A SQL keyword"
      ],
      "answer": 0,
      "explanation": "A primary key uniquely identifies each row."
    }
  ]
}
```

`description` and `explanation` are optional. Each question requires a unique ID, a prompt, exactly four options, and an answer index from 0 to 3.

## 6. Local API

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Check that the API is running. |
| GET | `/api/tests` | List saved tests. |
| POST | `/api/tests` | Validate and save a test. |
| GET | `/api/tests/:id` | Read test metadata. |
| DELETE | `/api/tests/:id` | Delete a test and its attempts. |
| POST | `/api/tests/:id/attempts` | Start or resume an attempt. |
| GET | `/api/attempts/:id` | Read active progress or a completed result. |
| PATCH | `/api/attempts/:id/answers` | Save answers using a revision number. |
| POST | `/api/attempts/:id/submit` | Submit and grade an attempt. |
| GET | `/api/history` | List completed attempts. |

## 7. Data model

### `mock_tests`

Stores `id`, `title`, `description`, `duration_minutes`, `question_count`, `test_json`, `created_at`, and `updated_at`.

### `attempts`

Stores `id`, `mock_test_id`, `status`, `answers_json`, `answer_revision`, `score`, `total_questions`, `percentage`, `completion_reason`, `started_at`, `expires_at`, and `completed_at`. Deleting a test cascades to its attempts. At most one attempt for a test may be active.

## 8. Quality requirements

- Primary workflows work from a 360 px viewport upward and support keyboard navigation and visible focus.
- Correctness is conveyed by labels or symbols as well as color.
- Active exam data never includes the answer key or explanation.
- Scores and deadlines are computed by the API, not accepted from the browser.
- Answer saves validate question IDs and option indexes, and detect stale revisions.
- Migrations run locally and preserve saved test and attempt data when ownership fields are removed.

## 9. Acceptance flow

1. Start local PostgreSQL and run the web app and API.
2. Import a valid JSON test and find it in the workspace after reload.
3. Start an exam, save answers, and verify that refresh preserves progress and deadline.
4. Submit and review the score, correct answers, and explanations.
5. Find the completed attempt in history and retake the test.
6. Export incorrect and unanswered questions as valid missed-question JSON.
